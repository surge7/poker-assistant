# Настройка бесплатного веб-хостинга в Yandex Cloud (без своего домена)

Сайт будет доступен по адресу **`https://ИМЯ_БАКЕТА.website.yandexcloud.net`** — свой домен не нужен. При размере приложения ~52 КБ и небольшом трафике плата **0 ₽/мес** (в пределах [бесплатного лимита](https://yandex.cloud/ru/docs/storage/pricing)).

---

## Что понадобится

- Аккаунт Яндекса
- Карта для привязки к биллингу (списаний не будет, пока не выйдете за free tier)
- 5–10 минут

---

## Шаг 1. Регистрация и биллинг

1. Откройте **[console.yandex.cloud](https://console.yandex.cloud)**.
2. Войдите по Яндексу или зарегистрируйтесь.
3. При первом входе создайте **биллинг-аккаунт**:
   - В консоли откроется предложение создать платёжный аккаунт.
   - Привяжите карту. Списаний не будет, пока потребление не превысит бесплатные лимиты (1 ГБ хранения, 100 К GET, 100 ГБ трафика в месяц).
4. Выберите или создайте **каталог** (Folder) — например «Покер-тренажёр» или оставьте «Default».

---

## Шаг 2. Создать бакет

Сервис Object Storage на дашборде каталога может быть не в боковом меню. Как попасть в него:

- **Вариант А.** Вверху страницы есть **«Поиск по сервисам»** — введите **Object Storage** или **Объектное хранилище**, откройте найденный сервис.
- **Вариант Б.** Нажмите **«Создать ресурс»** → в списке найдите **«Бакет»** или **Object Storage** и выберите создание бакета.
- **Вариант В.** В блоке **«Все сервисы»** (на дашборде каталога) прокрутите список и выберите **Object Storage** / **Объектное хранилище**.

После перехода в Object Storage:

1. Нажмите **Создать бакет**.
2. Заполните:
   - **Имя бакета** — уникальное в рамках всего Yandex Cloud, только латиница, цифры, дефис (например `poker-trainer-app`). Это имя войдёт в URL: `poker-trainer-app.website.yandexcloud.net`.
   - **Класс хранилища**: **Стандартное**.
   - **Доступ на чтение объектов**: **Публичный** (обязательно — иначе по адресу сайта будет 403 Forbidden). Если бакет уже создан без этого — включите публичный доступ в **Настройках** бакета (см. раздел «Если открывается 403 Forbidden» ниже).
   - Остальное можно не менять.
3. Нажмите **Создать бакет**.

---

## Шаг 3. Включить хостинг статического сайта

1. Откройте созданный бакет (клик по имени).
2. Перейдите на вкладку **Веб-сайт** (или **Настройки** → раздел про статический сайт).
3. Включите опцию **Хостинг статического сайта** (или **Веб-сайт**).
4. Укажите:
   - **Главная страница**: `index.html`
   - **Страница ошибки** (для SPA, чтобы при прямом переходе по путям открывался тот же index): `index.html`
5. Сохраните настройки.

После этого сайт будет отдаваться по адресу **`https://ИМЯ_БАКЕТА.website.yandexcloud.net`** (подставьте имя бакета).

---

## Если открывается 403 Forbidden (Access Denied)

Ошибка **403 Forbidden** с кодом **AccessDenied** значит, что бакет или объекты не отдаются публично. Нужно явно включить публичный доступ на чтение.

1. В консоли Yandex Cloud откройте **Object Storage** → выберите бакет `poker-trainer-app`.
2. Перейдите в **Настройки** бакета (вкладка или пункт меню «Настройки» / «Settings»).
3. Найдите пункт **«Публичный доступ»** или **«Доступ на чтение объектов»** / **«Доступ к списку объектов»**:
   - Установите **Публичный** (или **Public read**), чтобы любой мог читать объекты и открывать сайт.
   - Если есть отдельно «Доступ к списку объектов» — тоже сделайте **Публичный** (иначе главная страница по домену сайта может не отдаваться).
4. Сохраните настройки.
5. Убедитесь, что в бакете в **корне** лежит файл **`index.html`** и папка **`assets/`** с файлами (см. шаг 4). Пустой бакет или отсутствие `index.html` в корне тоже может приводить к ошибке доступа.

После сохранения подождите 1–2 минуты и обновите страницу `https://poker-trainer-app.website.yandexcloud.net`.

## Если открывается белый экран (но заголовок вкладки виден)

Заголовок вкладки («Покерный тренажер СР») берётся из `index.html`, значит главная страница отдаётся, но скрипты или стили не подгружаются — из‑за путей или типа контента.

**Что сделано в проекте:** в `vite.config.ts` задано **`base: './'`**, чтобы в сборке использовались относительные пути (`./assets/...`). Так файлы корректно загружаются на статическом хостинге (Yandex Cloud, S3).

**Что сделать вам:**

1. Пересоберите и заново загрузите файлы в бакет:
   ```bash
   cd apps/app && npm run build
   ```
   Затем в консоли Yandex Cloud загрузите **содержимое** папки `dist/` в корень бакета (замените существующие `index.html` и папку `assets/`).
2. Откройте сайт с принудительным обновлением (Ctrl+F5 или Cmd+Shift+R).

Если белый экран остаётся — откройте **Инструменты разработчика** (F12) → вкладка **Сеть (Network)** и проверьте, отдаются ли запросы к `assets/index-*.js` и `assets/index-*.css` с кодом 200. Во вкладке **Консоль (Console)** посмотрите, нет ли ошибок JavaScript.

## Если в консоли/сети 404 на JS и CSS

Ошибки **404** на `index-BJ7-dkXD.js`, `index-BkmB8QzO.css` (или похожие) означают: браузер запрашивает файлы, но в бакете их **нет по нужным путям**. Во вкладке **Сеть** такие запросы будут со статусом 404 (красные).

**Что проверить в бакете Yandex Cloud:**

1. Откройте бакет в консоли Object Storage.
2. В **корне** бакета должен быть файл **`index.html`** (не внутри папки).
3. Должна быть «папка» **`assets`**, а внутри неё — файлы **`index-BJ7-dkXD.js`** и **`index-BkmB8QzO.css`** (имена из текущей сборки; после новой сборки могут быть другие, с новым хешем).

В Object Storage нет папок как таковых: путь к объекту — это ключ. Файл из `dist/assets/index-BJ7-dkXD.js` должен лежать в бакете с ключом **`assets/index-BJ7-dkXD.js`**, а не просто `index-BJ7-dkXD.js` в корне.

**Как загрузить правильно:**

- Загружайте **содержимое** папки `dist/`:
  - в корень бакета — один файл **`index.html`**;
  - затем загрузите **содержимое** папки `dist/assets/` так, чтобы в бакете получились объекты **`assets/index-XXXX.js`** и **`assets/index-XXXX.css`** (в интерфейсе это часто делается выбором папки `assets` при загрузке или загрузкой двух файлов с префиксом `assets/`).
- В русской консоли Yandex: **Загрузить объекты** → добавьте `index.html`, затем добавьте файлы из папки `assets`; при загрузке из папки убедитесь, что путь в бакете сохраняется как `assets/имя_файла`.

После загрузки обновите страницу с очисткой кэша (Ctrl+F5). Ошибка **404 на favicon.ico** не мешает работе приложения — это просто отсутствие иконки вкладки.

**Важно:** имя папки в бакете должно быть **`assets`** (строчными буквами). Если загрузить как `Assets` или `ASSETS`, пути в `index.html` (`./assets/...`) не совпадут и будет 404. Не переименовывайте папку при загрузке.

## Шаг 4. Собрать и загрузить файлы

### 4.1. Собрать проект

В корне приложения (папка `apps/app`):

```bash
npm run build
```

В папке `dist/` появятся `index.html` и папка `assets/` с JS и CSS.

### 4.2. Загрузить в бакет через консоль

1. В консоли Yandex Cloud откройте бакет.
2. Нажмите **Загрузить объекты** (или **Upload**).
3. Загрузите **всё содержимое** папки `dist/`:
   - файл **`index.html`** — в **корень** бакета (не в подпапку);
   - папку **`assets`** — целиком (внутри должны быть файлы вида `index-XXXX.js` и `index-XXXX.css`).

Структура в бакете должна быть такой (имя папки **`assets`** — строчными буквами, иначе будет 404):

```
бакет
├── index.html
└── assets/
    ├── index-XXXX.js
    └── index-XXXX.css
```

4. Дождитесь окончания загрузки.

## Обновление сайта (повторная загрузка)

После изменений в коде:

1. Выполните снова: `npm run build`.
2. В консоли Yandex Cloud откройте бакет и **загрузите заново** файлы из `dist/` (можно заменить существующие объекты теми же именами). Либо используйте скрипт деплоя ниже — он перезаливает только изменённые файлы.

## Опционально: деплой из командной строки (AWS CLI)

Чтобы не заходить каждый раз в консоль, можно заливать `dist/` командой. Нужны **статический ключ доступа** к Object Storage и установленный **AWS CLI** (Yandex Object Storage совместим с S3 API).

### Создать ключ доступа в Yandex Cloud

1. В консоли: **IAM** → **Сервисные аккаунты** (или **Service accounts**).
2. Создайте сервисный аккаунт (например `storage-deploy`) с ролью **storage.editor** (или **editor** на каталог).
3. Откройте этот сервисный аккаунт → вкладка **Создать новый ключ** → **Создать статический ключ доступа**.
4. Сохраните **Key ID** и **Secret Key** — Secret больше не покажут.

### Настроить AWS CLI для Yandex

Установите [AWS CLI](https://aws.amazon.com/cli/), затем:

```bash
aws configure --profile yandex
```

- **AWS Access Key ID**: вставьте Key ID из шага выше  
- **AWS Secret Access Key**: вставьте Secret Key  
- **Default region name**: `ru-central1`  
- **Default output format**: можно оставить пустым или `json`

### Скрипт деплоя

В проекте есть скрипт `deploy-yandex.sh`. Перед первым запуском:

1. Создайте файл `apps/app/.env.yandex` (файл в .gitignore, в репозиторий не попадёт):

```bash
YANDEX_BUCKET=poker-trainer-app
export AWS_ACCESS_KEY_ID="ваш Key ID"
export AWS_SECRET_ACCESS_KEY="ваш Secret Key"
```

2. Выполните (из папки `apps/app`):

```bash
./deploy-yandex.sh
```

или с явным указанием бакета:

```bash
YANDEX_BUCKET=poker-trainer-app ./deploy-yandex.sh
```

Если вы настроили доступ через профиль (`aws configure --profile yandex`), а не через переменные в `.env.yandex`, запускайте:

```bash
AWS_PROFILE=yandex ./deploy-yandex.sh
```

Через npm: `npm run deploy:yandex` (переменные или профиль должны быть заданы).

Скрипт соберёт проект (`npm run build`) и загрузит содержимое `dist/` в бакет с помощью `aws s3 sync` (endpoint Yandex). Для работы нужен установленный [AWS CLI](https://aws.amazon.com/cli/).

## Как посмотреть использование и не платить лишнего

**Где смотреть потребление**

1. В консоли Yandex Cloud откройте **Биллинг** (в меню слева или через поиск по сервисам — «Биллинг»).
2. На дашборде биллинга видны **баланс**, **потребление за период** и **активные гранты** (если есть).
3. Раздел **Детализация** (или **Отчёты**) — по каждому сервису и ресурсу: сколько израсходовано хранения, запросов, трафика и сколько за это начислено. Можно отфильтровать по сервису **Object Storage** и по каталогу.

**Когда будут списывать деньги**

Списывают только за то, что **превышает бесплатный лимит** каждый месяц:

| Ресурс | Бесплатно в месяц | После лимита |
|--------|--------------------|--------------|
| Хранение (стандарт) | первый **1 ГБ** | платно за каждый ГБ сверх |
| Запросы GET | первые **100 000** | платно за каждые 10 000 сверх |
| Запросы PUT/LIST и т.п. | первые **10 000** | платно за каждые 10 000 сверх |
| Исходящий трафик | первые **100 ГБ** | платно за каждый ГБ сверх |

У вас сайт ~52 КБ и небольшой трафик — в типичном случае вы остаётесь **внутри лимита**, плата **0 ₽**. Списание возможно только если, например, трафик вырастет больше 100 ГБ в месяц или вы начнёте хранить в этом же облаке много других данных.

**Как не переплатить**

- Периодически заходите в **Биллинг** → смотрите «Потребление» и «Детализация». Пока потребление по Object Storage укладывается в лимиты выше — платить не за что.
- При желании в биллинге можно создать **бюджет** и включить уведомления (например, при пороге 100 ₽) — так вы узнаете, если что-то начнёт списываться.

Официальные лимиты и тарифы: [тарификация Object Storage](https://yandex.cloud/ru/docs/storage/pricing).
