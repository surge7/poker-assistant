# Соответствие алгоритмов программы лучшим практикам и книгам

Краткое сравнение логики тренажёра с общепринятыми формулами и рекомендациями из покерной литературы (Sklansky, Harrington, гайды по пот-оддсам, Rule of 2/4, GTO-базы).

---

## 1. Пот-оддсы и требуемая эквити

**Формула в книгах:**  
*Required Equity = Call Amount / (Pot + Call)* — колл математически оправдан, если ваша эквити ≥ этой доли.

**В программе:**  
`requiredEquity = toCall / (potSize + toCall)` — совпадает с классической формулой.

**Вывод:** соответствие.

---

## 2. Эквити (Монте-Карло)

**В книгах:** эквити — доля выигрыша против диапазона оппонента; часто считают по симуляции или по таблицам.

**В программе:** симуляция Монте-Карло против случайных рук оппонентов (без заданного диапазона). Детерминированный сид для воспроизводимости.

**Отличие:** в реальной игре оппоненты играют диапазонами (не случайные руки). Для тренажёра «против N случайных рук» — разумное упрощение; для более точной стратегии нужны диапазоны (GTO/солверы).

**Вывод:** для учебного тренажёра — приемлемо; явно не заменяет солвер.

---

## 3. Ауты и вероятность улучшения (Rule of 2 и 4)

**В книгах:**  
- **Rule of 2:** одна карта впереди → вероятность ≈ outs × 2% (например, 9 аутов ≈ 18%).  
- **Rule of 4:** две карты впереди (флоп → ривер) → ≈ outs × 4% (9 аутов ≈ 36%).  
- Точная формула для двух улиц: `1 - (1 - outs/47)(1 - outs/46)`.

**В программе:**  
- В `countOuts` для флопа используется точная формула двух улиц: `IMPROVE_RULE.twoCards(outs)`.  
- В `totalOuts` для совета раньше использовался `improveChance = total/remaining` (одна улица), что на флопе занижало шанс добрать дро.

**Исправление:** для флопа (3 карты на борде) в совете использовать вероятность на две улицы; для терна/ривера — на одну.

**Вывод:** после правки — соответствие правилу 2/4 и точным формулам.

---

## 4. Позиция

**В книгах:** поздняя позиция (BTN, CO) позволяет играть шире; ранняя — уже; позиция влияет на фолд/колл.

**В программе:**  
- `isLatePosition`: BTN (0) и последняя позиция считаются поздними.  
- Пороги фолда в поздней позиции мягче (например, foldBarPct не ниже 14% vs 22%; допуск по эквити 1.05 vs 1.1; callThreshold −5% vs 0%).

**Вывод:** соответствие идее «позиция смягчает фолд».

---

## 5. Премиум-руки на префлопе

**В книгах:**  
- AA, KK, QQ, JJ — почти всегда играем (рейз/колл).  
- TT и ниже — по ситуации, пот-оддсам и стекам; мелкие пары часто фолд при рейзах и плохих оддсах.

**В программе:**  
- Только AA–JJ считаются «премиум-парами» с советом «рейз/колл» без фолда по «слабости».  
- TT, 99, …, 22 проходят общую логику по эквити и пот-оддсам — возможен фолд.

**Вывод:** соответствие.

---

## 6. Сильная рука и натс

**В книгах:** натс и очень сильные руки (фулл-хаус и выше) — рейз для значения.

**В программе:**  
- Натс определяется перебором лучшей руки на борде; при совпадении с нашей рукой — «натс».  
- Рейз рекомендуется при натсе или при rank ≥ FullHouse.

**Вывод:** соответствие.

---

## 7. Дро и пот-оддсы

**В книгах:** если шанс улучшения (по аутам) ≥ требуемой эквити для колла — колл математически оправдан (прямые пот-оддсы).

**В программе:** при `outs >= 8` и `improveChance >= requiredEquity` совет «колл» с пояснением по аутам и требуемой эквити.

**Вывод:** соответствие при корректном `improveChance` (см. п. 3).

---

## 8. Чего нет в программе (ограничения)

- **Имплайд-оддсы:** в книгах дро могут коллить с худшими прямыми оддсами, если ожидают добор с улицы и доп. выигрыш. В программе учитываются только текущий банк и колл — имплайд не моделируется.  
- **Диапазоны оппонентов:** эквити считается против случайных рук, а не против типичных диапазонов (рейз, колл, 3-бет и т.д.).  
- **Размер ставки и стиль:** нет явной модели «оппонент платит на следующих улицах» или «тесный/лузовый».  
- **Стек (BB):** нет явного учёта глубины стека (сеты, аллы, push/fold).  
- **Мультивей:** логика по сути «против N оппонентов»; тонкости мультивея (доп. эквити, блокеры) не различаются.

Эти пункты можно добавлять по шагам (например, «режим: только пот-оддсы» vs «упрощённые имплайд»).

---

## 9. Рекомендации по доработке

1. **totalOuts.improveChance:** на флопе (board.length === 3) использовать вероятность на две улицы `twoCards(total)`; на терне/ривере — на одну улицу `total/remaining`.  
2. **Перекрытие аутов:** при суммировании аутов (флеш + стрит) часть карт общая; при желании можно вводить «эффективные ауты» или не суммировать жёстко, а брать максимум из категорий или комбинированную вероятность.  
3. **Явная пометка в UI:** «Совет по прямым пот-оддсам; имплайд-оддсы и диапазоны не учитываются».  
4. **Опционально:** отдельный режим «алл-ин на флопе» (только две карты впереди) для согласованности с Rule of 4.

| Компонент              | Соответствие | Комментарий |
|------------------------|-------------|-------------|
| Формула пот-оддсов     | Да          | toCall/(pot+toCall) |
| Эквити Монте-Карло     | Частично    | Против случайных рук; без диапазонов |
| Rule of 2/4, ауты      | Да (после правки) | Флоп — две улицы; терн/ривер — одна |
| Позиция                | Да          | Поздняя смягчает фолд |
| Премиум-пары префлоп   | Да          | Только AA–JJ «всегда играем» |
| Сильная рука / натс    | Да          | Рейз для значения |
| Дро + пот-оддсы        | Да          | При корректном improveChance |
| Имплайд-оддсы          | Нет         | Не реализованы |
| Диапазоны оппонентов  | Нет         | Случайные руки |

После правки `improveChance` для флопа алгоритм по прямой математике и базовым правилам из книг соответствует лучшим практикам в рамках заявленной модели (пот-оддсы, эквити против N случайных рук, позиция, премиум-руки).
