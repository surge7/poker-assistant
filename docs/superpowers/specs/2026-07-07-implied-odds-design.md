# Фича: упрощённые имплайд-оддсы (карманные пары + сильные дро)

**Дата:** 2026-07-07
**Ветка:** `main` (continuation)
**Целевая версия:** v1.5.0
**Предыдущий релиз:** v1.4.0 (ускорение автопересчёта + профили)

---

## 1. Контекст и мотивация

Контркейс: рука **7♥ 7♦** на префлопе, pot=30, call=15, 6 игроков → совет **FOLD** с причиной «эквити 21% при требуемых 33%». Это **математически прав в рамках текущей модели** (только pot-оддсы), но **контринтуитивен для реальной стратегии**: 77 в поздней позиции коллят ради сет-майнинга (~11.8% поймать сет на флопе, и тогда выигрывают значительно больше колла).

`docs/STRATEGY_ALIGNMENT.md` §8 уже фиксирует это ограничение: «в программе учитываются только текущий банк и колл — имплайд не моделируется». Эта фича добавляет упрощённые имплайд-оддсы для двух главных кейсов, где они сильнее всего влияют на решение.

## 2. Цели

1. **Сет-майнинг для карманных пар.** Карманные пары 22–TT на префлопе (не премиум AA–JJ) получают «имплайд-скидку»: колл оправдан, если эквити ≥ 65% от требуемой.
2. **Сильные дро на флопе.** Дро с аутами ≥ 8 (флеш-дро 9, OESD 8) на флопе: колл оправдан при эквити ≥ 75% от требуемой. Монстр-дро (флеш+стрит, ауты ≥ 13): ≥ 65%.
3. **Явное объяснение.** В reason совета добавляется фраза про имплайд-оддсы, чтобы пользователь понимал, почему колл оправдан несмотря на «низкую» эквити.
4. **Обратная совместимость.** Без имплайд-кейсов (всё остальное) поведение не меняется — 79 тестов остаются зелёными.

## 3. Нецели

- Не добавляем поле «эффективный стек» в UI (его нет).
- Не моделируем полные имплайд-оддсы со стеком (правило 15:1 и т.д.).
- Не трогаем слабые дро (gutshot 4 аута) — остаются по чистым pot-оддсам.
- Не меняем UI (`apps/app`).

## 4. Архитектура

Изменения только в `packages/core/src/`:

```
config/
└── thresholds.ts        MODIFY: +константы имплайдов (3 коэффициента)
strategy/
└── advice.ts            MODIFY: +2 ветки имплайдов, +фразы в reason
strategy/
└── advice.test.ts       MODIFY: +тесты на имплайды (пары, дро, обратная совместимость)
```

Новых модулей и файлов нет — имплайды — это модификация порогов в существующем `advice.ts`.

### 4.1. Концепция

Вместо полного моделирования будущих ставок, используем **коэффициенты к требуемой эквити**:

```
effectiveRequiredEquity = requiredEquity * impliedFactor
```

где `impliedFactor` зависит от типа руки:
- **карманная пара 22–TT на префлопе** (сет-майнинг): `impliedFactor = 0.65` — колл оправдан при 65% от pot-odds требуемой.
- **сильное дро ≥ 8 аутов на флопе**: `impliedFactor = 0.75`.
- **монстр-дро ≥ 13 аутов на флопе** (флеш+стрит): `impliedFactor = 0.65`.
- **всё остальное**: `impliedFactor = 1.0` (без имплайдов, как раньше).

Контркейс 7-7: `requiredEquity = 33%`, с `impliedFactor = 0.65` → `effectiveRequired = 21.5%`. Наша эквити 21% ≈ 21.5% → колл оправдан (на грани, в BTN).

## 5. Детали модулей

### 5.1. `config/thresholds.ts` — константы

```ts
/**
 * Коэффициенты имплайд-оддсов: во сколько раз снижаем требуемую эквити
 * для рук с потенциальной выгодой от улучшения.
 * 1.0 = без имплайдов (чистые pot-оддсы).
 *
 * Сет-майнинг (карманные пары 22-TT на префлопе): сет ~11.8%, но выигрыш
 * превышает колл в несколько раз → 0.65 (колл при 65% от требуемой).
 * Сильное дро (аутов ≥ 8 на флопе): реализуется на ривере, добираем → 0.75.
 * Монстр-дро (аутов ≥ 13, флеш+стрит): почти гарантия → 0.65.
 */
export const IMPLIED_PAIR_FACTOR = 0.65;
export const IMPLIED_STRONG_DRAW_FACTOR = 0.75;
export const IMPLIED_MONSTER_DRAW_FACTOR = 0.65;
export const IMPLIED_MONSTER_DRAW_OUTS = 13;  // порог монстр-дро
```

### 5.2. `strategy/advice.ts` — расчёт `impliedFactor`

В начале `getAdvice`, после расчёта `requiredEquity` и `outs`, но до основных веток:

```ts
// Имплайд-оддсы: снижаем требуемую эквити для рук с потенциальной выгодой.
let impliedFactor = 1.0;
let impliedReason = '';
if (phase === 'preflop' && isPocketPair(holeCards) && !isPremiumPocketPair(holeCards)) {
  // Сет-майнинг: карманные пары 22-TT (не премиум).
  impliedFactor = IMPLIED_PAIR_FACTOR;
  impliedReason = 'сет-майнинг';
} else if (board.length >= 3 && board.length < 5) {
  // Дро на флопе/терне (новые карты ещё придут).
  if (outs >= IMPLIED_MONSTER_DRAW_OUTS) {
    impliedFactor = IMPLIED_MONSTER_DRAW_FACTOR;
    impliedReason = 'монстр-дро';
  } else if (outs >= 8) {
    impliedFactor = IMPLIED_STRONG_DRAW_FACTOR;
    impliedReason = 'сильное дро';
  }
}
const effectiveRequiredEquityPct = requiredEquityPct * impliedFactor;
```

Затем `effectiveRequiredEquityPct` используется ВМЕСТО `requiredEquityPct` в порогах фолда:
- `foldBarPct` (порог фолда «слабая рука»)
- `lowEqFoldMargin` (фолд «эквити ниже требуемой»)
- `margin` (сравнение для borderline call/fold)
- `callThreshold` сравнения

В reason при `impliedFactor < 1.0` добавляется фраза:
```
` Имплайд-оддсы (${impliedReason}): колл оправдан при эквити ≥ ${Math.round(effectiveRequiredEquityPct)}% от требуемых ${Math.round(requiredEquityPct)}%.`
```

### 5.3. Что меняется в существующих ветках

`foldBarPct` пересчитывается с `effectiveRequiredEquityPct` вместо `requiredEquityPct`:
```ts
const foldBarPct = toCall > 0
  ? Math.max(effectiveRequiredEquityPct * FOLD_EQUITY_MULTIPLIER, latePos ? FOLD_BAR_LATE_PCT : FOLD_BAR_EARLY_PCT) * pfrModifier
  : 100;
```

`lowEqFoldMargin` и `margin` тоже используют `effectiveRequiredEquityPct`:
```ts
if (eq < effectiveRequiredEquityPct * lowEqFoldMargin) ...
const margin = eq - effectiveRequiredEquityPct;
```

`requiredEquityPct` (оригинальная) остаётся для отображения в reason («требуемых ~X%»), но решения принимаются по `effectiveRequiredEquityPct`.

## 6. Поведение на контркейсе 7-7

| Параметр | Значение |
|----------|----------|
| Рука | 7♥ 7♦ (карманная пара, не премиум) |
| Фаза | префлоп |
| pot/call | 30/15 |
| requiredEquity (pot-odds) | 33% |
| impliedFactor | 0.65 (сет-майнинг) |
| **effectiveRequiredEquity** | **21.5%** |
| наша эквити | 21% |
| margin | 21 − 21.5 = −0.5% |

В BTN (`callThreshold = -5`): margin −0.5 ≥ -5 → **CALL** (вместо прежнего FOLD).
В ранней позиции (`callThreshold = 0`): margin −0.5 < 0 → **FOLD** (позиция строже).

Reason включает: «Имплайд-оддсы (сет-майнинг): колл оправдан при эквити ≥ 22% от требуемых 33%.»

| Риск | Митигация |
|------|-----------|
| Коэффициент 0.65/0.75 слишком агрессивен → лузовые коллы | Калибровать на реальных раздачах; вынести в config (перенастраиваемо) |
| Без стека имплайды неточны (в коротком стеке сет-майнинг убыточен) | Документировать ограничение; в UI будущего — поле стека |
