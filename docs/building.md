# Сборка и развёртывание

Единое руководство по сборке и публикации приложения: веб-версия (локально), Android APK и веб-хостинги. Объединяет пять прежних руководств BUILD_*.md (удалены из apps/app; содержание перенесено сюда без потерь).

## Web (локально)

После сборки приложение — это статические файлы (HTML, JS, CSS). Их можно разместить на любом хостинге статики — варианты см. в разделе «Web-хостинги» ниже.

### Собрать веб-версию

Из папки приложения:

```bash
cd apps/app
npm install
npm run build
```

В папке **dist/** появятся файлы для публикации: `index.html` и папка `assets/`. Эту папку **dist/** (или её содержимое) нужно загрузить на хостинг.

### Проверить приложение без телефона и без APK (эмулятор)

Можно запускать приложение в **эмуляторе Android** в Android Studio — APK не нужен, телефон не нужен.

Скачайте и установите: [developer.android.com/studio](https://developer.android.com/studio). При первом запуске дождитесь установки SDK.

2. Нажмите **Create Device**.
3. Выберите устройство (например **Pixel 6**) → **Next**.
4. Выберите образ системы (например **API 34**, **Tiramisu**) — при необходимости нажмите **Download** рядом с образом → **Next**.
5. Имя оставьте или измените → **Finish**.

#### 3. Открыть проект и запустить в эмуляторе

В терминале:

```bash
cd /Users/gpbu25522/Projects/poker-assistant/apps/app
npx cap open android
```

В Android Studio:

1. Дождитесь синхронизации Gradle (если спросят — согласитесь).
2. Вверху выберите ваше виртуальное устройство в списке устройств (или нажмите на него в Device Manager, чтобы запустить эмулятор).
3. Нажмите **Run** (зелёный треугольник) или **Run → Run 'app'** (Shift+F10).

Приложение соберётся и установится в эмулятор, откроется на экране эмулятора. APK никуда копировать не нужно.

**Если меняли веб-код** — перед запуском в эмуляторе выполните:

```bash

npm run build
npx cap sync android
```

затем в Android Studio снова **Run → Run 'app'**.

### Скриншоты 9:16 для стора (RuStore и др.) в Android Studio

RuStore и другие магазины требуют скриншоты **строго 9:16** (например 720×1280, 1080×1920, 1440×2560). Если загрузить кадр с другим соотношением, стор обрежет его и модерация может отклонить. В Android Studio удобно делать скриншоты сразу в 9:16, если эмулятор запущен с таким разрешением.

#### 1. Виртуальное устройство с разрешением 1080×1920 (9:16)

1. В Android Studio: **Tools** → **Device Manager**.
2. Нажмите **Create Device**.
3. В списке устройств выберите устройство с разрешением **1080×1920** (9:16):
   - Если есть, например **Pixel 2** (1080×1920) — выберите его → **Next**.
   - Если подходящего нет: нажмите **New Hardware Profile**, задайте **Resolution** ширина **1080**, высота **1920** → **Finish**, затем выберите этот профиль → **Next**.
4. Выберите образ системы (например **API 34**) → **Next** → **Finish**.

#### 2. Запустить приложение в этом эмуляторе

1. Вверху выберите созданное устройство (1080×1920).
2. Нажмите **Run** (зелёный треугольник) — приложение откроется в эмуляторе.
3. Перейдите на нужные экраны (главный, карты, результаты и т.д.) — для каждого экрана сделаете отдельный скриншот.

#### 3. Сделать скриншот

1. В окне эмулятора справа на панели найдите иконку **камеры** (**Take screenshot**).
2. Либо откройте меню **⋯** (три точки) → **Take screenshot**.
3. Либо нажмите **Ctrl+S** (Windows/Linux) или **Cmd+S** (Mac).
4. В диалоге выберите **Save** и укажите папку (например `store-screenshots-input` в проекте). Имя по умолчанию — `Screenshot_ГГГГММДД-ЧЧММСС.png`.

Разрешение сохранённого файла будет **1080×1920** (9:16) — его можно сразу загружать в RuStore. Если в консоли рекомендуют JPG 1080×1920, положите PNG в папку **store-screenshots-input/** и выполните `npm run store-screenshots` — в **store-screenshots/** появятся JPG 1080×1920.

#### 4. Загрузить в RuStore

В консоли разработчика в блоке «Скриншоты приложения для телефона» загрузите **только** эти файлы (1080×1920, 9:16). Не загружайте скриншоты с обычного телефона — у него другое соотношение сторон, стор их обрежет.

Подробнее о требованиях RuStore: [Правила к приложениям](https://help.rustore.ru/rustore/for_developers/publishing_and_verifying_apps/requirement_apps).

### Release-сборка для пользователей (Google Play и установка вручную)

Debug-APK подходит для тестов. Для публикации в Google Play и для установки пользователями нужна **подписанная release-сборка**.

#### 1. Создать keystore (один раз)

В терминале (например, в папке `apps/app/android`):

```bash
keytool -genkey -v -keystore upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias my-key-alias
```

Укажите пароли и данные (ФИО, организация и т.д.). Файл `upload-keystore.jks` и пароли **обязательно сохраните** — без них нельзя будет обновлять приложение в маркете.

#### 2. Настроить подпись

В папке `apps/app/android`:

1. Скопируйте пример: `cp keystore.properties.example keystore.properties`
2. Откройте `keystore.properties` и укажите реальные значения:

```properties
storeFile=upload-keystore.jks
storePassword=ваш_пароль_хранилища
keyAlias=my-key-alias
keyPassword=ваш_пароль_ключа
```

Путь `storeFile` — относительно папки `android` (например, просто `upload-keystore.jks`, если файл лежит в `android/`). Файл `keystore.properties` в git не коммитить (он уже в `.gitignore`).

#### 3. Собрать release

Из папки приложения:

```bash
cd apps/app
npm run android:release
```

или:

```bash
cd apps/app
./build-android-release.sh
```

Скрипт соберёт веб, синхронизирует с Android и запустит `bundleRelease` и `assembleRelease`.

#### 4. Где искать файлы

- **AAB (для Google Play):** `apps/app/app-release.aab` — загружайте в Google Play Console (Release → Production или тестовый трек).
- **APK (для установки вручную):** `apps/app/app-release.apk` — можно раздавать пользователям напрямую (почта, сайт и т.д.).

В Android Studio release можно собрать так: **Build** → **Generate App Bundles or APKs** → **Android App Bundle** или **APK**, выберите **release** и укажите существующий keystore (тот же, что в `keystore.properties`).

## Web-хостинги

После сборки приложение — это статические файлы (HTML, JS, CSS). Их можно разместить на любом хостинге статики. Ниже — самые простые и бесплатные варианты: быстрые варианты (Netlify, Vercel, Cloudflare Pages, GitHub Pages), а также подробные пошаговые инструкции для Yandex Cloud, VK Cloud (Ru-Cloud) и Cloudflare Pages.

### Что указать на хостинге

| Параметр           | Значение        |
|--------------------|-----------------|
| Корневая папка     | **dist**        |
| Build command      | `npm run build` |
| Node version       | 18+ (если нужен) |

Приложение одностраничное (SPA), маршрутизации по URL нет — дополнительная настройка (redirects для SPA) не нужна.

### Свой домен (опционально)

На Netlify, Vercel и Cloudflare Pages в настройках сайта можно добавить свой домен (например `poker-trainer.example.com`). DNS записи подскажет сам сервис; обычно это CNAME на их адрес.

### Быстрые варианты хостинга (бесплатный тариф)

#### Вариант A: Netlify (проще всего)

1. Зарегистрируйтесь на [netlify.com](https://www.netlify.com).
2. Перетащите папку **dist** в зону «Drag and drop your site output folder» на [app.netlify.com/drop](https://app.netlify.com/drop).
3. Сайт появится по адресу вида `random-name-123.netlify.app`. В настройках можно задать своё имя и подключить свой домен.

**Через Git (автодеплой при push):**  
Подключите репозиторий в Netlify → в настройках сборки укажите: **Build command** `npm run build`, **Publish directory** `apps/app/dist` (или `dist` если в Netlify открыт только `apps/app`).

#### Вариант B: Vercel

1. Зарегистрируйтесь на [vercel.com](https://vercel.com).
2. Установите CLI: `npm i -g vercel`.
3. Из папки приложения выполните:
   ```bash
   cd apps/app
   npm run build
   vercel
   ```
4. Следуйте подсказкам (путь к проекту — текущая папка, output — **dist**). Сайт получит адрес вида `poker-assistant-xxx.vercel.app`.

**Через Git:** импортируйте репозиторий в Vercel, укажите **Root Directory** `apps/app`, **Build Command** `npm run build`, **Output Directory** `dist`.

#### Вариант C: Cloudflare Pages (коротко)

1. Зарегистрируйтесь на [dash.cloudflare.com](https://dash.cloudflare.com).
2. **Workers & Pages** → **Create** → **Pages** → **Connect to Git** (или **Upload assets**).
3. При подключении Git: выберите репозиторий, **Build command** `npm run build`, **Build output directory** `dist`. При загрузке вручную — загрузите содержимое папки **dist**.
4. Сайт будет по адресу `project-name.pages.dev`.

Подробная пошаговая инструкция (ручная загрузка и автодеплой из корня монорепозитория) — в разделе «Cloudflare Pages» ниже.

#### Вариант D: GitHub Pages

1. Репозиторий на GitHub. В настройках репозитория: **Pages** → Source: **GitHub Actions** (или **Deploy from a branch**).
2. Если сайт будет по адресу `username.github.io/репозиторий/`, в **vite.config.ts** добавьте `base: '/имя-репозитория/'` (со слэшами), затем снова `npm run build`.
3. Для **Deploy from a branch**: выберите ветку (например `main`) и папку **/ (root)** или отдельную папку, куда будете пушить содержимое **dist** (часто используют ветку `gh-pages` или подпапку `docs` с содержимым dist).

**Через GitHub Actions:** создайте workflow, который при push запускает `npm run build` и публикует папку `dist` в GitHub Pages (шаблоны есть в документации GitHub Pages).

### Yandex Cloud: бесплатный веб-хостинг без своего домена

Сайт будет доступен по адресу **`https://ИМЯ_БАКЕТА.website.yandexcloud.net`** — свой домен не нужен. При размере приложения ~52 КБ и небольшом трафике плата **0 ₽/мес** (в пределах [бесплатного лимита](https://yandex.cloud/ru/docs/storage/pricing)).

#### Что понадобится

- Аккаунт Яндекса
- Карта для привязки к биллингу (списаний не будет, пока не выйдете за free tier)
- 5–10 минут

#### Шаг 1. Регистрация и биллинг

1. Откройте **[console.yandex.cloud](https://console.yandex.cloud)**.
2. Войдите по Яндексу или зарегистрируйтесь.
3. При первом входе создайте **биллинг-аккаунт**:
   - В консоли откроется предложение создать платёжный аккаунт.
   - Привяжите карту. Списаний не будет, пока потребление не превысит бесплатные лимиты (1 ГБ хранения, 100 К GET, 100 ГБ трафика в месяц).
4. Выберите или создайте **каталог** (Folder) — например «Покер-тренажёр» или оставьте «Default».

#### Шаг 2. Создать бакет

Сервис Object Storage на дашборде каталога может быть не в боковом меню. Как попасть в него:

- **Вариант А.** Вверху страницы есть **«Поиск по сервисам»** — введите **Object Storage** или **Объектное хранилище**, откройте найденный сервис.
- **Вариант Б.** Нажмите **«Создать ресурс»** → в списке найдите **«Бакет»** или **Object Storage** и выберите создание бакета.
- **Вариант В.** В блоке **«Все сервисы»** (на дашборде каталога) прокрутите список и выберите **Object Storage** / **Объектное хранилище**.

После перехода в Object Storage:

1. Нажмите **Создать бакет**.
2. Заполните:
   - **Имя бакета** — уникальное в рамках всего Yandex Cloud, только латиница, цифры, дефис (например `poker-trainer-app`). Это имя войдёт в URL: `poker-trainer-app.website.yandexcloud.net`.
   - **Класс хранилища**: **Стандартное**.
   - **Доступ на чтение объектов**: **Публичный** (обязательно — иначе по адресу сайта будет 403 Forbidden). Если бакет уже создан без этого — включите публичный доступ в **Настройках** бакета (см. раздел «Если открывается 403 Forbidden» ниже).
   - Остальное можно не менять.
3. Нажмите **Создать бакет**.

#### Шаг 3. Включить хостинг статического сайта

1. Откройте созданный бакет (клик по имени).
2. Перейдите на вкладку **Веб-сайт** (или **Настройки** → раздел про статический сайт).
3. Включите опцию **Хостинг статического сайта** (или **Веб-сайт**).
4. Укажите:
   - **Главная страница**: `index.html`
   - **Страница ошибки** (для SPA, чтобы при прямом переходе по путям открывался тот же index): `index.html`
5. Сохраните настройки.

После этого сайт будет отдаваться по адресу **`https://ИМЯ_БАКЕТА.website.yandexcloud.net`** (подставьте имя бакета).

#### Если открывается 403 Forbidden (Access Denied)

Ошибка **403 Forbidden** с кодом **AccessDenied** значит, что бакет или объекты не отдаются публично. Нужно явно включить публичный доступ на чтение.

1. В консоли Yandex Cloud откройте **Object Storage** → выберите бакет `poker-trainer-app`.
2. Перейдите в **Настройки** бакета (вкладка или пункт меню «Настройки» / «Settings»).
3. Найдите пункт **«Публичный доступ»** или **«Доступ на чтение объектов»** / **«Доступ к списку объектов»**:
   - Установите **Публичный** (или **Public read**), чтобы любой мог читать объекты и открывать сайт.
   - Если есть отдельно «Доступ к списку объектов» — тоже сделайте **Публичный** (иначе главная страница по домену сайта может не отдаваться).
4. Сохраните настройки.
5. Убедитесь, что в бакете в **корне** лежит файл **`index.html`** и папка **`assets/`** с файлами (см. шаг 4). Пустой бакет или отсутствие `index.html` в корне тоже может приводить к ошибке доступа.

После сохранения подождите 1–2 минуты и обновите страницу `https://poker-trainer-app.website.yandexcloud.net`.

#### Если открывается белый экран (но заголовок вкладки виден)

Заголовок вкладки («Покерный тренажер СР») берётся из `index.html`, значит главная страница отдаётся, но скрипты или стили не подгружаются — из‑за путей или типа контента.

**Что сделано в проекте:** в `vite.config.ts` задано **`base: './'`**, чтобы в сборке использовались относительные пути (`./assets/...`). Так файлы корректно загружаются на статическом хостинге (Yandex Cloud, S3).

**Что сделать вам:**

1. Пересоберите и заново загрузите файлы в бакет:
   ```bash
   cd apps/app && npm run build
   ```
   Затем в консоли Yandex Cloud загрузите **содержимое** папки `dist/` в корень бакета (замените существующие `index.html` и папку `assets/`).
2. Откройте сайт с принудительным обновлением (Ctrl+F5 или Cmd+Shift+R).

Если белый экран остаётся — откройте **Инструменты разработчика** (F12) → вкладка **Сеть (Network)** и проверьте, отдаются ли запросы к `assets/index-*.js` и `assets/index-*.css` с кодом 200. Во вкладке **Консоль (Console)** посмотрите, нет ли ошибок JavaScript.

#### Если в консоли/сети 404 на JS и CSS

Ошибки **404** на `index-BJ7-dkXD.js`, `index-BkmB8QzO.css` (или похожие) означают: браузер запрашивает файлы, но в бакете их **нет по нужным путям**. Во вкладке **Сеть** такие запросы будут со статусом 404 (красные).

**Что проверить в бакете Yandex Cloud:**

1. Откройте бакет в консоли Object Storage.
2. В **корне** бакета должен быть файл **`index.html`** (не внутри папки).
3. Должна быть «папка» **`assets`**, а внутри неё — файлы **`index-BJ7-dkXD.js`** и **`index-BkmB8QzO.css`** (имена из текущей сборки; после новой сборки могут быть другие, с новым хешем).

В Object Storage нет папок как таковых: путь к объекту — это ключ. Файл из `dist/assets/index-BJ7-dkXD.js` должен лежать в бакете с ключом **`assets/index-BJ7-dkXD.js`**, а не просто `index-BJ7-dkXD.js` в корне.

**Как загрузить правильно:**

- Загружайте **содержимое** папки `dist/`:
  - в корень бакета — один файл **`index.html`**;
  - затем загрузите **содержимое** папки `dist/assets/` так, чтобы в бакете получились объекты **`assets/index-XXXX.js`** и **`assets/index-XXXX.css`** (в интерфейсе это часто делается выбором папки `assets` при загрузке или загрузкой двух файлов с префиксом `assets/`).
- В русской консоли Yandex: **Загрузить объекты** → добавьте `index.html`, затем добавьте файлы из папки `assets`; при загрузке из папки убедитесь, что путь в бакете сохраняется как `assets/имя_файла`.

После загрузки обновите страницу с очисткой кэша (Ctrl+F5). Ошибка **404 на favicon.ico** не мешает работе приложения — это просто отсутствие иконки вкладки.

**Важно:** имя папки в бакете должно быть **`assets`** (строчными буквами). Если загрузить как `Assets` или `ASSETS`, пути в `index.html` (`./assets/...`) не совпадут и будет 404. Не переименовывайте папку при загрузке.

#### Как посмотреть использование и не платить лишнего

**Где смотреть потребление**

1. В консоли Yandex Cloud откройте **Биллинг** (в меню слева или через поиск по сервисам — «Биллинг»).
2. На дашборде биллинга видны **баланс**, **потребление за период** и **активные гранты** (если есть).
3. Раздел **Детализация** (или **Отчёты**) — по каждому сервису и ресурсу: сколько израсходовано хранения, запросов, трафика и сколько за это начислено. Можно отфильтровать по сервису **Object Storage** и по каталогу.

**Когда будут списывать деньги**

Списывают только за то, что **превышает бесплатный лимит** каждый месяц:

| Ресурс | Бесплатно в месяц | После лимита |
|--------|--------------------|--------------|
| Хранение (стандарт) | первый **1 ГБ** | платно за каждый ГБ сверх |
| Запросы GET | первые **100 000** | платно за каждые 10 000 сверх |
| Запросы PUT/LIST и т.п. | первые **10 000** | платно за каждые 10 000 сверх |
| Исходящий трафик | первые **100 ГБ** | платно за каждый ГБ сверх |

У вас сайт ~52 КБ и небольшой трафик — в типичном случае вы остаётесь **внутри лимита**, плата **0 ₽**. Списание возможно только если, например, трафик вырастет больше 100 ГБ в месяц или вы начнёте хранить в этом же облаке много других данных.

**Как не переплатить**

- Периодически заходите в **Биллинг** → смотрите «Потребление» и «Детализация». Пока потребление по Object Storage укладывается в лимиты выше — платить не за что.
- При желании в биллинге можно создать **бюджет** и включить уведомления (например, при пороге 100 ₽) — так вы узнаете, если что-то начнёт списываться.

Официальные лимиты и тарифы: [тарификация Object Storage](https://yandex.cloud/ru/docs/storage/pricing).

### Ru-Cloud: VK Cloud и Yandex Cloud — статический сайт при минимальном трафике и размере

#### Размер этого приложения (минимум)

После `npm run build` папка **dist** занимает примерно **52 КБ**:

#### Опционально: кэширование (Cache-Control)

Чтобы браузеры реже повторно запрашивали одни и те же файлы, при загрузке объектов можно задать заголовок **Cache-Control** (в настройках объекта в консоли или через S3 API):

- Для **index.html**: `Cache-Control: no-cache` или короткий `max-age=60` (чтобы обновления подхватывались быстрее).
- Для **assets/*.js** и **assets/*.css** (имена с хешем): `Cache-Control: public, max-age=31536000` (год) — при следующем билде имена файлов изменятся, пользователи получат новую версию.

Это не меняет тарификацию облака, но снижает число GET-запросов и трафик при повторных визитах.

В папке **apps/app/dist/** появятся файлы: `index.html` и папка `assets/`. Это и есть готовый сайт.

##### Шаг 1.2. Создать сайт в Cloudflare Pages (Upload)

1. В [dash.cloudflare.com](https://dash.cloudflare.com) в левом меню выберите **Workers & Pages**.
2. Нажмите **Create** → **Pages** → **Connect to Git**.
3. Вверху переключитесь на вкладку **Upload assets** (или нажмите **Create a project** и выберите **Direct Upload**).
4. В поле **Project name** введите, например: `poker-trainer`.
5. Нажмите **Upload** (или перетащите папку).
6. Выберите **всё содержимое** папки **apps/app/dist/** (не саму папку `dist`, а то, что внутри: файл `index.html` и папка `assets`). Можно выделить все файлы и папки внутри `dist` и перетащить в окно браузера, либо заархивировать содержимое `dist` в один ZIP и загрузить ZIP — Cloudflare распакует его.
7. Нажмите **Deploy site**.

Через минуту сайт будет доступен по адресу вида **https://poker-trainer.pages.dev** (имя зависит от введённого Project name).

##### Обновление сайта (ручная загрузка)

После изменений в коде снова выполните `npm run build` (в `apps/app` или `npm run build:app` из корня), затем в Cloudflare Pages: **Workers & Pages** → ваш проект → **Create deployment** → снова загрузите содержимое **apps/app/dist/**.

#### Способ 2: Подключение Git (автодеплой при push)

Подходит, если репозиторий уже на **GitHub** или **GitLab**. При каждом push в выбранную ветку Cloudflare сам соберёт проект и обновит сайт.

##### Шаг 2.1. Репозиторий на GitHub

Убедитесь, что проект **poker-assistant** залит в GitHub (или GitLab). Если нет — создайте репозиторий на GitHub и выполните:

```bash
cd /путь/к/poker-assistant
git remote add origin https://github.com/ВАШ_ЛОГИН/poker-assistant.git
git push -u origin main
```

(подставьте свой URL репозитория и ветку, например `main`).

##### Шаг 2.2. Подключить репозиторий к Cloudflare Pages

1. В [dash.cloudflare.com](https://dash.cloudflare.com) откройте **Workers & Pages** → **Create** → **Pages** → **Connect to Git**.
2. Выберите **GitHub** (или GitLab), при необходимости разрешите доступ Cloudflare к аккаунту и репозиториям.
3. В списке репозиториев выберите **poker-assistant** (или как он называется у вас).
4. Нажмите **Begin setup**.

##### Шаг 2.3. Настройки сборки (Build configuration)

На экране **Set up builds and deployments** укажите:

| Поле | Значение |
|------|----------|
| **Production branch** | `main` (или ваша основная ветка) |
| **Build command** | `npm ci && npm run build:app` |
| **Build output directory** | `apps/app/dist` |

- **Framework preset** можно оставить **None** или выбрать **Vite** (если есть в списке; настройки выше важнее).
- **Root directory** оставьте пустым (сборка идёт из корня репозитория).
- Переменные окружения (Environment variables) для этого проекта не обязательны.

Если в корне репо нет скрипта `build:app`, используйте в **Build command**:

```bash
npm ci && cd apps/app && npm run build
```

**Build output directory** тогда по-прежнему: **apps/app/dist**.

##### Шаг 2.4. Запуск первого деплоя

1. Нажмите **Save and Deploy** (или **Deploy site**).
2. Дождитесь окончания сборки (обычно 1–3 минуты). В логе должны быть шаги `npm ci`, сборка приложения и публикация папки `apps/app/dist`.
3. После успешного деплоя сайт откроется по адресу вида **https://poker-assistant.pages.dev** (имя проекта можно изменить в настройках).

##### Дальнейшие обновления

При каждом **push** в ветку **main** (или выбранную Production branch) Cloudflare автоматически запустит сборку и обновит сайт. Заходить в панель и загружать файлы вручную не нужно.

#### Шаг 3. Имя проекта и свой домен (по желанию)

1. В **Workers & Pages** откройте ваш проект.
2. Вкладка **Custom domains** — нажмите **Set up a custom domain** и введите свой домен (например `poker.example.com`). Cloudflare подскажет, какую DNS-запись создать.
3. Имя поддомена **\*.pages.dev** можно изменить в **Settings** → **Project name** (при первом создании или позже, если сервис разрешает).

#### Краткая шпаргалка (Cloudflare Pages)

**Ручная загрузка (без Git):**

1. `cd apps/app && npm run build` (или из корня: `npm run build:app`).
2. Cloudflare: **Workers & Pages** → **Create** → **Pages** → **Upload assets**.
3. Имя проекта → загрузить **содержимое** папки **apps/app/dist/** → **Deploy site**.

**Через Git:**

1. Репо на GitHub/GitLab.
2. Cloudflare: **Workers & Pages** → **Create** → **Pages** → **Connect to Git** → выбрать репо.
3. **Build command:** `npm ci && npm run build:app`  
   **Build output directory:** `apps/app/dist`  
   **Save and Deploy**.

После первого успешного деплоя ссылка на сайт будет в панели проекта (например **https://poker-trainer.pages.dev**).

### Кратко (все варианты)

1. **Сборка:** `npm run build` → папка **dist/**.
2. **Хостинг:** загрузить **dist** на Netlify Drop, Vercel, Cloudflare Pages или GitHub Pages.
3. Для автодеплоя при каждом push — подключить Git к Netlify/Vercel/Cloudflare и указать команду сборки и папку **dist**.

После публикации веб-версия будет доступна по выданному URL (и по своему домену, если его подключите).
